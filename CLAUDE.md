# CLAUDE.md

Redcord.cz renewal: a **review prototype** (concept for owner review, not a production service), built against `docs/Redcord_Nextjs_Redesign_Coding_Prompt_v0.1.md`. Site copy and UI are Czech; code, comments and docs are English. README.md covers layout and the real-vs-fixture status. This file covers rules and traps.

## Commands

```bash
pnpm dev                 # :3000 (via scripts/next.mjs, see Windows note)
pnpm check               # typecheck + vitest + build: run before calling work done
pnpm test                # vitest: packages/*/src/**/*.test.ts, apps/*/src/**/*.test.ts
pnpm review              # Playwright QA + screenshots against a running :3000 server
pnpm inventory:compare --base=http://localhost:3100   # inventory:new/compare default to :3000
```

## Windows / Git Bash

- Don't call `next` directly from package scripts. `scripts/next.mjs` sets `process.title` before spawning Next, because pnpm's Node aborts with `Assertion failed: process_title … util.c` when the Git Bash console title is empty.
- Only one `next dev` can run per app folder. If the user's server holds :3000, don't kill it. Test with `pnpm build && node scripts/next.mjs start -p 3100` instead.
- `next.config.ts` (and so `redirects.ts`) is read at server start. Redirect changes need a server restart.
- Git Bash rewrites `/paths` in arguments to `C:/Program Files/Git/...`. Watch for this in curl loops.

## Next.js version

Next 16.4 / React 19.3 / Tailwind 4.3 differ from older training data (async `params`/`searchParams`, `@theme` tokens, `@source` for workspace packages). Read `apps/redcord-web/node_modules/next/dist/docs/` before using an unfamiliar API. `apps/redcord-web/AGENTS.md` is regenerated by `next dev`; leave it alone.

## Content and provenance rules (from the spec)

- Every content record has `SourceMeta` with an `ApprovalState`: `approved | pending | proposal | illustrative`. Preview (`SITE_ENV` unset/`preview`) renders non-approved records with review badges. Production renders `approved` only. Keep that filter in `isVisible` / `resolveMedia`. Don't bypass it in components.
- **Never invent** metrics, testimonials, practitioners, prices, course dates, booking URLs or safety instructions. Missing data → honest empty state or `ReviewNote`. Illustrative course dates exist only behind `showIllustrativeSessions`.
- Enquiries use the test adapter only. Never send real messages, take payments, deploy, or change DNS.
- Shop, course registration and Redpoint Clinic are external handoffs (`packages/integrations/src/handoffs.ts`). Don't rebuild them. `REDPOINT_BOOKING_URL` comes from the owner. Never guess it.
- Don't copy redcord.com / Wix code, fonts or images. redcord.cz content is owner-authorised (owner: AHAMA).

## Migration map

`apps/redcord-web/src/config/redirects.ts` drives `next.config.ts` redirects and `docs/MIGRATION_MAP.md`.

- Statuses: `keep`, `decided` (308), `proposed` (307, preview only), `needs-owner` / `gone` (no `to`).
- `to` is an app path listed in `APP_ROUTES`, or an https URL on `EXTERNAL_REDIRECT_HOSTS`. Fragment targets need an entry in `REQUIRED_ANCHORS`.
- No chains, no blanket redirects to `/`. `redirects.test.ts` enforces all of this. When adding a route, add it to `APP_ROUTES`.
- Update `docs/MIGRATION_MAP.md` in the same change.

## Images

Media slots live in `packages/content/src/media/slots.json`. `registry.generated.json` is **generated** by `pnpm images:promote` from `assets-inbox/redcord-cz/review.csv` (`;`-separated, with BOM). Don't hand-edit the registry. `assets-inbox/` is gitignored and not served. Open its `index.html` from disk.

## Crawling redcord.cz

Its WAF answers 401/429 when hit hard. Scripts crawl at 1 req/s, cache under `inventory/old/cache/` and `assets-inbox/`, and stop on 401/403/429. Reuse the cache. Don't add `--refresh` or lower `--delay` without a reason.

## Gotchas

- Enquiry rate limit (5 per 10 min) is in memory. Restart the server between `pnpm review` runs.
- Docs to keep current: `docs/ASSUMPTIONS_AND_INPUTS.md`, `MIGRATION_MAP.md`, `ASSET_MANIFEST.md`, `PRODUCTION_BACKLOG.md`, `VERIFICATION.md`.
